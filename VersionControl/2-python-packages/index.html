    Building a Python Package

    Building on Git Basics and GitHub Collaboration, this tutorial teaches you to structure Python code as an installable package.

    Why Packaging?

    Single-file scripts work for simple projects, but as complexity grows, packages provide:

    • Organization: Logical grouping of related code
    • Reusability: Install and import from anywhere
    • Dependency management: Declare what your project needs
    • Versioning: Semantic versioning for releases
    • Distribution: Share via PyPI, conda, GitHub
    • Testing: Easier to test modular code
    • Documentation: Standard structure for docs

    Package Anatomy

    A well-structured Python package looks like:

    my_project/
├── my_package/          # Main package (Python code)
│   ├── __init__.py      # Marks as package, defines API
│   ├── module1.py       # Code modules
│   ├── module2.py
│   └── subpackage/
│       ├── __init__.py
│       └── module3.py
├── tests/               # Unit tests
│   ├── __init__.py
│   ├── test_module1.py
│   └── test_module2.py
├── docs/                # Documentation
│   ├── index.md
│   └── api.md
├── examples/            # Example scripts
│   └── basic_usage.py
├── .gitignore           # Git ignore patterns
├── README.md            # Project description
├── LICENSE              # Open source license
├── setup.py             # Package configuration (legacy)
├── setup.cfg            # Package metadata
├── pyproject.toml       # Modern Python project config
└── MANIFEST.in          # Include non-Python files

    Modern Python Packaging: pyproject.toml

    The modern standard is pyproject.toml (PEP 517, 518, 621). This replaces separate setup.py and setup.cfg files.

    Basic pyproject.toml

    [build-system]
requires = ["setuptools>=61.0", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "my-package"
version = "0.1.0"
description = "A brief description of what your package does"
readme = "README.md"
requires-python = ">=3.8"
license = {text = "MIT"}
authors = [
    {name = "Your Name", email = "your.email@example.com"},
]
keywords = ["keyword1", "keyword2"]
classifiers = [
    "Development Status :: 3 - Alpha",
    "Intended Audience :: Developers",
    "License :: OSI Approved :: MIT License",
    "Programming Language :: Python :: 3",
    "Programming Language :: Python :: 3.8",
    "Programming Language :: Python :: 3.9",
    "Programming Language :: Python :: 3.10",
    "Programming Language :: Python :: 3.11",
]

dependencies = [
    "numpy>=1.20",
    "scipy>=1.7",
]

[project.optional-dependencies]
dev = ["pytest>=6.0", "black", "flake8", "mypy"]
docs = ["sphinx", "sphinx-rtd-theme"]

[project.urls]
"Homepage" = "https://github.com/username/my-package"

[tool.setuptools]
packages = ["my_package"]

[tool.setuptools.package-data]
my_package = ["data/*.csv"]

    Creating Your Package Structure

    Step 1: Create Directory Structure

    mkdir my_project
cd my_project
git init
mkdir my_package tests docs examples

    Step 2: Create __init__.py

    This file marks a directory as a Python package and defines the public API.

    # my_package/__init__.py

"""
My Package - A description of your package

This package provides tools for calculating astronomical distances.
"""

__version__ = "0.1.0"

from .module1 import calculate_distance
from .module2 import AngularVelocity

__all__ = [
    "calculate_distance",
    "AngularVelocity",
]

    Why this matters: Users can now do:

    from my_package import calculate_distance

# Instead of:
from my_package.module1 import calculate_distance

    Step 3: Organize Your Code

    # my_package/module1.py

"""Calculations for astronomical distances"""

import numpy as np


def calculate_distance(ra1, dec1, ra2, dec2):
    """
    Calculate great-circle distance between two points on a sphere.

    Uses the Haversine formula.

    Parameters
    ----------
    ra1, dec1 : float
        Right ascension and declination of first point (degrees)
    ra2, dec2 : float
        Right ascension and declination of second point (degrees)

    Returns
    -------
    distance : float
        Angular distance in degrees
    """
    # Convert to radians
    ra1, dec1, ra2, dec2 = np.radians([ra1, dec1, ra2, dec2])

    # Haversine formula
    dra = ra2 - ra1
    ddec = dec2 - dec1
    a = np.sin(ddec/2)**2 + np.cos(dec1) * np.cos(dec2) * np.sin(dra/2)**2
    c = 2 * np.arcsin(np.sqrt(a))

    return np.degrees(c)

    Step 4: Create Tests

    Tests verify your code works correctly and document expected behavior.

    # tests/test_module1.py

import pytest
import numpy as np
from my_package.module1 import calculate_distance


def test_calculate_distance_same_point():
    """Distance between a point and itself should be 0"""
    distance = calculate_distance(0, 0, 0, 0)
    assert distance == pytest.approx(0.0)


def test_calculate_distance_pole_to_equator():
    """Distance from pole to equator should be ~90 degrees"""
    distance = calculate_distance(0, 90, 0, 0)
    assert distance == pytest.approx(90.0, abs=1e-10)


def test_calculate_distance_array_input():
    """Should handle array inputs"""
    ra1 = np.array([0, 10])
    dec1 = np.array([0, 0])
    ra2 = np.array([1, 11])
    dec2 = np.array([0, 0])

    distance = calculate_distance(ra1, dec1, ra2, dec2)
    assert len(distance) == 2

    Step 5: Create Setup Files

    Modern approach with pyproject.toml (recommended):

    Create pyproject.toml with the configuration above.

    Legacy approach with setup.py (for compatibility):

    # setup.py

from setuptools import setup, find_packages

setup(
    name="my-package",
    version="0.1.0",
    description="A brief description",
    author="Your Name",
    author_email="your.email@example.com",
    url="https://github.com/username/my-package",
    packages=find_packages(),
    python_requires=">=3.8",
    install_requires=[
        "numpy>=1.20",
        "scipy>=1.7",
    ],
    extras_require={
        "dev": ["pytest", "black", "flake8"],
        "docs": ["sphinx"],
    },
)

    Installing Your Package

    Development Installation

    # Install in development mode (editable)
# Changes to source code are immediately reflected
pip install -e .

# Or with dev dependencies:
pip install -e ".[dev]"

    Regular Installation

    # Build and install
pip install .

# From a specific directory
pip install /path/to/my_project

    Using Virtual Environments

    # Create isolated environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install your package
pip install -e ".[dev]"

# Deactivate environment
deactivate

    Testing Your Package

    # Install pytest
pip install pytest

# Run tests
pytest

# Run with verbose output
pytest -v

# Run specific test file
pytest tests/test_module1.py

# Run with coverage
pip install pytest-cov
pytest --cov=my_package

    Building Distributions

    # Install build tools
pip install build

# Build source and wheel distributions
python -m build

# Creates:
# dist/my_package-0.1.0.tar.gz  (source distribution)
# dist/my_package-0.1.0-py3-none-any.whl  (wheel)

    Publishing to GitHub

    # Commit all files
git add .
git commit -m "Initial package structure"

# Add GitHub remote
git remote add origin https://github.com/username/my_package.git

# Push to GitHub
git push -u origin main

    Best Practices

    1. Use semantic versioning: MAJOR.MINOR.PATCH
    2. Write docstrings: Use NumPy or Google style
    3. Add type hints: Improves code clarity
    4. Version in one place: Define __version__ once (in __init__.py or pyproject.toml)
    5. Use .gitignore: Exclude build artifacts, virtual environments
