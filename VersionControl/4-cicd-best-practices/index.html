    CI/CD and Code Quality: Automate Your Workflow

    Building on previous tutorials, this covers Continuous Integration/Continuous Deployment and practices to maintain code quality automatically.

    What is CI/CD?

    Continuous Integration (CI): Automatically run tests and checks on every commit/PR.

    Continuous Deployment (CD): Automatically build, test, and release packages.

    Benefits: - Catch bugs before merging - Maintain code quality standards - Reduce manual work - Build user confidence - Speed up development

    GitHub Actions

    GitHub Actions are workflows that run on GitHub's servers in response to repository events.

    Basic Workflow Structure

    Create .github/workflows/tests.yml:

    name: Tests

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ['3.8', '3.9', '3.10', '3.11']

    steps:
    - uses: actions/checkout@v3

    - name: Set up Python
      uses: actions/setup-python@v4
      with:
        python-version: ${{ matrix.python-version }}

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -e ".[dev]"

    - name: Run tests
      run: pytest

    - name: Run linting
      run: flake8 my_package tests

    Testing on Multiple Python Versions

    The matrix strategy tests your code on multiple Python versions automatically:

    strategy:
  matrix:
    python-version: ['3.8', '3.9', '3.10', '3.11']
    os: [ubuntu-latest, macos-latest, windows-latest]

    Code Quality Tools

    Automated Testing: pytest

    Unit tests verify your code works correctly.

    pip install pytest pytest-cov

    # tests/test_calculations.py

import pytest
from my_package import calculate_distance


def test_zero_distance():
    """Test distance between identical points"""
    result = calculate_distance(0, 0, 0, 0)
    assert result == pytest.approx(0.0)


def test_invalid_input():
    """Test invalid input raises error"""
    with pytest.raises(ValueError):
        calculate_distance(None, 0, 0, 0)


class TestDistance:
    """Test suite for distance calculations"""

    def test_hemisphere(self):
        """Test antipodal points"""
        result = calculate_distance(0, 0, 0, -90)
        assert result == pytest.approx(90.0)

    Run tests:

    pytest
pytest -v                    # Verbose
pytest tests/test_file.py    # Specific file
pytest -k "test_zero"        # Matching pattern
pytest --cov=my_package      # With coverage

    Code Formatting: black

    Automatic code formatting ensures consistency.

    pip install black

    # .github/workflows/format.yml

name: Format Check

on: [push, pull_request]

jobs:
  format:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    - uses: actions/setup-python@v4
    - run: pip install black
    - run: black --check my_package tests

    Apply formatting: 

    black my_package tests   # Apply formatting
black --check my_package # Check without changing

    Linting: flake8

    Static code analysis finds bugs and style issues.

    pip install flake8

    Rules: - E/W: PEP 8 errors/warnings - F: Logical errors (undefined variables, etc.) - C: Complexity issues

    flake8 my_package tests

    Configure in setup.cfg:

    [flake8]
max-line-length = 100
exclude = .git,__pycache__,.venv
ignore = E203,W503

    Conventional Commits

    Standardized commit messages enable: - Automatic changelog generation - Automatic versioning - Better history readability

    Format

    <type>(<scope>): <subject>

<body>

<footer>

    Types: - feat: New feature - fix: Bug fix - docs: Documentation - style: Formatting (no code change) - refactor: Code refactor (no behavior change) - perf: Performance improvement - test: Adding/updating tests - ci: CI/CD changes - chore: Other changes

    Examples:

    feat(distance): add Haversine calculation

Implements the Haversine formula for calculating great-circle
distances between two celestial coordinates.

Closes #42

    fix(distance): handle edge case with negative coordinates

The distance calculation failed when coordinates were negative
due to integer conversion. Fixed by using float throughout.

Fixes #87

    Pre-commit Hooks

    Automatically run checks before committing code locally.

    pip install pre-commit

    Create .pre-commit-config.yaml:

    repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.4.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-added-large-files
      - id: check-merge-conflict

  - repo: https://github.com/psf/black
    rev: 23.3.0
    hooks:
      - id: black
        language_version: python3.10

  - repo: https://github.com/PyCQA/flake8
    rev: 6.0.0
    hooks:
      - id: flake8
        args: ['--max-line-length=100']

  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.2.0
    hooks:
      - id: mypy
        additional_dependencies: ['types-all']

  - repo: https://github.com/commitizen-tools/commitizen
    rev: 3.2.2
    hooks:
      - id: commitizen
        stages: [commit-msg]

    Install hooks: 

    pre-commit install

# Or for commit-msg hook:
pre-commit install --hook-type commit-msg

    Test hooks: 

    pre-commit run --all-files

    Complete CI/CD Workflow

    Testing Workflow

    .github/workflows/tests.yml:

    name: Tests

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
        python-version: ['3.8', '3.9', '3.10', '3.11']

    steps:
    - uses: actions/checkout@v3

    - name: Set up Python
      uses: actions/setup-python@v4
      with:
        python-version: ${{ matrix.python-version }}

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -e ".[dev]"

    - name: Lint with flake8
      run: |
        flake8 my_package tests

    - name: Check types with mypy
      run: mypy my_package

    - name: Test with pytest
      run: pytest --cov=my_package

    - name: Upload coverage
      uses: codecov/codecov-action@v3
      with:
        file: ./coverage.xml

    Publishing Workflow

    .github/workflows/publish.yml:

    name: Publish to PyPI

on:
  push:
    tags:
      - 'v*'

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    - uses: actions/setup-python@v4
      with:
        python-version: '3.10'

    - name: Install build tools
      run: pip install build twine

    - name: Build distribution
      run: python -m build

    - name: Check build
      run: twine check dist/*

    - name: Publish to PyPI
      uses: pypa/gh-action-pypi-publish@release/v1
      with:
        password: ${{ secrets.PYPI_API_TOKEN }}

    Setup: Go to repo Settings → Secrets → New repository secret: - Name: PYPI_API_TOKEN - Value: Your PyPI API token

    Release Workflow

    .github/workflows/release.yml:

    name: Create Release

on:
  push:
    tags:
      - 'v*'

jobs:
  create-release:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3

    - name: Create Release
      uses: softprops/action-gh-release@v1
      with:
        draft: false
        prerelease: false
        generate_release_notes: true

    Deployment Best Practices

    1. Version everything: Tags, releases, Docker images
    2. Automate releases: GitHub Actions + PyPI
    3. Release notes: Auto-generate from commits
    4. Breaking changes: Clearly document in release notes
    5. Rollback plan: Tag previous versions
    6. Monitor health: Check package downloads and issues

    Troubleshooting

    Workflow not triggering

    • Check branch/tag names match on: conditions
    • Verify file path: .github/workflows/filename.yml
    • Check permissions in repo settings

    Tests pass locally but fail in CI

    • Different Python version
    • Missing dependencies
    • Platform-specific issues (Windows vs Unix)
    • Different environment variables

    Badge not updating

    • Workflow must succeed once first
    • Use raw GitHub content URLs: badge.svg?branch=main
